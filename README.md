# tg-summary-bot

Телеграм-бот, который копит сообщения группового чата и раз в сутки публикует в тот же чат
краткую сводку: о чём говорили с прошлого раза. Сводку пишет языковая модель через
[OpenRouter](https://openrouter.ai/); текст задаётся промптом, который лежит обычным файлом
и правится без перезапуска.

Бот нужен тем, кому некогда читать чат целиком. Поэтому сводка короткая: промпт держит её в
пределах 2000 знаков, а к каждой теме идёт ссылка на начало обсуждения — кому интересно,
открывает и читает подряд.

Вот как выглядит готовый пост (содержание вымышленное):

> Что обсуждали 20–22 июля
>
> **Проявка просроченной плёнки**
> Иван не смог получить цвет на плёнке с истёкшим сроком — кадры уходили в зелень. Сошлись
> на том, что снимать такую плёнку нужно с запасом по экспозиции, а правку цвета оставлять
> на скан.
> → обсуждение
>
> **Сканеры под средний формат**
> Сравнивали три модели по цене и разрешению. К единому мнению не пришли: у каждой нашлись
> свои ограничения по держателям плёнки.
> → обсуждение
>
> Ещё говорили про выбор ноутбука и спорили о механических клавиатурах.

Слова «→ обсуждение» в чате — ссылки на первое сообщение темы.

## Как устроено

Бот получает обновления по long polling и складывает в базу SQLite текст сообщений и подписи
к вложениям из всех видимых ему групп. Раз в пять минут срабатывает проверка расписания: если
для чата настроено время публикации и оно наступило, бот берёт из базы сообщения, накопившиеся
с прошлой сводки, подставляет их в промпт, отправляет модели и публикует ответ в чат.

Три решения, которые стоит знать заранее:

- **Сводка всегда строится по базе**, а не по живому потоку. Поэтому тестовый прогон и
  боевая публикация — один и тот же код над одними данными.
- **Сводка охватывает не календарные сутки**, а всё, что написано с прошлой публикации.
  Отметка места сдвигается только при успешной публикации.
- **У каждого чата один статус публикации на день.** Если к назначенному времени сообщений
  меньше порога, бот помечает день пропущенным и до завтра к этому чату не возвращается —
  даже если к вечеру переписка разошлась. Повторная попытка в тот же день бывает только
  после технического сбоя.

Подробно замысел и устройство описаны в [`docs/спецификация.md`](docs/спецификация.md),
формат подачи сообщений модели и разбор её ответа — в
[`docs/требования_к_данным.md`](docs/требования_к_данным.md).

## Что понадобится

- Сервер с Docker и Docker Compose (либо Python 3.12 для локального запуска).
- Бот, созданный у [@BotFather](https://t.me/BotFather), — его токен.
- Ключ [OpenRouter](https://openrouter.ai/keys) и выбранная модель.
- Ваш числовой id в Telegram — узнать у [@userinfobot](https://t.me/userinfobot).
- Прокси — только если Telegram или OpenRouter недоступны напрямую с вашего сервера.

## Установка

**1. Подготовьте бота у @BotFather.** Создайте бота, заберите токен. Затем командой
`/setprivacy` **отключите режим приватности** — иначе бот увидит в группе только сообщения,
адресованные ему лично.

**2. Добавьте бота в чат.** Лучше сразу администратором: без прав администратора он не
получает уведомления о реакциях, а на реакциях держится отметка важных сообщений. Достаточно
администратора без единого права.

**3. Разверните код.**

```bash
git clone https://github.com/vladimir-kharin/tg-summary-bot.git
cd tg-summary-bot
cp .env.example .env
cp config/chats.example.yaml config/chats.yaml
```

**4. Заполните `.env`** — токен, ваш id, ключ OpenRouter, модель. Прокси оставьте пустым,
если он не нужен.

**5. Запустите:**

```bash
docker compose up -d --build
```

База создастся сама, отдельного шага установки нет.

**6. Узнайте id чата.** Отправьте боту в личные сообщения `/status`: чат, в который вы его
добавили, появится в разделе «Без настроек» вместе со своим id. Впишите этот id в
`config/chats.yaml` вместо id из примера — настройка применится при следующей проверке
расписания, максимум через пять минут.

## Настройка чатов

Всё, что бот видит, он пишет в базу. Публикует он только в те чаты, что перечислены в
`config/chats.yaml`; если чата в файле нет, сообщения копятся, но сводка не публикуется.

```yaml
default_chat: -1001234567890   # чат для /test, когда id не указан явно

chats:
  -1001234567890:
    name: Сообщество            # своё название, видно в /status; необязательно
    prompt: default             # файл prompts/default.md
    min_messages: 10            # меньше сообщений за период — день пропускается
    time: "09:00"               # МСК; поля нет — автопубликация выключена
    mark:                       # отметка важных сообщений; необязательно
      reaction: "🔥"            # какой реакцией отмечать
      by: [123456789]           # чьи реакции считать метками
```

- Все поля, кроме идентификатора чата, необязательны. По умолчанию `min_messages` — 30,
  `prompt` — `default`.
- **Автопубликация включается наличием поля `time`.** Если удалить `time`, сообщения
  продолжат копиться и `/test` будет работать, но в чат ничего не уйдёт.
- Настройки перечитываются на каждом тике, перезапуск не нужен. Нужен немедленный эффект —
  `docker compose restart`.
- **Время публикации считается по Москве** (UTC+3) независимо от часового пояса сервера.
  Пояс задан константой `MSK` в [`scheduler.py`](scheduler.py) — для другого часового пояса
  поменяйте её.

Отмеченные сообщения (`mark`) работают так: вы ставите выбранную реакцию на важное сообщение,
и бот передаёт его модели отдельным блоком «отмечено важным» — так тема с большей
вероятностью попадёт в сводку. Бот видит только те реакции, что поставлены после того, как он
стал администратором чата; за прошлое их не получить, кроме как загрузкой выгрузки. Кастомные
премиум-реакции не поддерживаются: вместо символа у них внутренний идентификатор.

## Промпт

Промпты лежат в `prompts/`, поле `prompt` в настройке чата указывает имя файла без
расширения. Файл читается с диска на каждом прогоне — правка действует сразу.

В репозитории два файла:

- **`prompts/default.md`** — шаблон. В начале блок «Чат», который нужно заполнить под своё
  сообщество: о чём чат, кто читает сводку, что считается «по теме». От этого блока зависит
  отбор тем, так что заполнять его стоит подробно.
- **`prompts/example_1c.md`** — живой промпт, по которому бот работает в чатах курса по
  разработке в 1С с помощью ИИ. Это пример подробного описания темы: перечислены предметная
  область, инструменты и типичные вопросы.

Бот подставляет в промпт два плейсхолдера: `{{MESSAGES}}` — все сообщения периода,
`{{HIGHLIGHTED}}` — отмеченные реакцией. Модель должна вернуть обычный текст с двумя
служебными метками: `##` в начале строки — заголовок темы, `[[id]]` — место ссылки на
обсуждение. Бот экранирует ответ и сам добавляет разметку, поэтому сломать её модель не может.
Он же дописывает в конец поста хэштег `#сводка` — по нему сводки удобно искать в чате; сам
хэштег задан константой `HASHTAG` в [`postprocess.py`](postprocess.py). Правила подстановки и
разбора ответа — в [`docs/требования_к_данным.md`](docs/требования_к_данным.md).

Обкатывать промпт удобно командой `/test`: правите файл, отправляете `/test`, смотрите
результат. К ответу идёт служебная строка с моделью, временем и стоимостью прогона — по ней
сравнивают варианты промптов и моделей.

## Команды в личке

В личных сообщениях бот отвечает только владельцу — тому, чей id указан в `OWNER_ID`.
В групповых чатах команд нет.

| Команда | Что делает |
|---|---|
| `/test [сколько] [id чата]` | Тестовая сводка по последним N сообщениям. По умолчанию 30 сообщений и чат из `default_chat`. Отметку места не двигает, в чат ничего не публикует |
| `/status` | Состояние: чаты, накопление, состояние дня, отметки, ошибки |

**Загрузка истории** — не команда: отправьте боту файл `result.json`, он разберёт его и
ответит отчётом.

## Загрузка истории чата

Бот видит только сообщения, пришедшие после его добавления в чат. Всё, что было раньше,
загружают выгрузкой: Telegram Desktop → чат → ⋮ → «Экспорт истории чата» → формат **JSON**,
медиа отключить. Полученный `result.json` отправьте боту в личные сообщения.

Дубли отсекаются по паре «чат и номер сообщения», поэтому выгрузку можно слать повторно и с
пересечением периодов. Облачный Bot API не отдаёт файлы больше 20 МБ — крупные выгрузки
режьте по периодам и присылайте частями.

## Эксплуатация

### Один экземпляр на токен

У бота один токен. Запустите два процесса одновременно — например, локальный `bot.py` и
контейнер на сервере — и Telegram отдаст `Conflict: terminated by other getUpdates`,
обновления начнут теряться. Перед локальной отладкой останавливайте серверный контейнер, и
наоборот.

### Что требует перезапуска, а что нет

| Изменили | Что делать |
|---|---|
| `prompts/*.md` | ничего — промпт читается на каждом прогоне |
| `config/chats.yaml` | ничего — настройки перечитываются на каждом тике (до 5 минут). Нужно сразу — `docker compose restart` |
| `.env` | `docker compose up -d` — переменные читаются при запуске контейнера |
| код (`*.py`) | `docker compose up -d --build` |

`config/`, `prompts/`, `data/` подключены томами: лежат на диске рядом с проектом и переживают
пересборку. Код живёт внутри образа и меняется только пересборкой.

### Повседневные команды

```bash
docker compose ps            # состояние контейнера
docker compose logs -f       # живой лог
docker compose restart       # перезапуск
docker compose down          # остановить
tail -40 data/bot.log        # лог событий бота
```

В `data/bot.log` пишутся только события: публикация сводки, ошибка, пропуск дня по недобору,
импорт выгрузки, тестовый прогон. Проверки расписания, на которых ничего не произошло, в лог
не идут. Ротация по размеру: до 10 МБ, хранятся три предыдущих файла.

### Состояния дня

Показываются в `/status` и хранятся в базе:

- `waiting` — сегодня ещё не публиковали, ждём набора и времени;
- `skipped` — сообщений было меньше порога, день пропущен;
- `done` — сводка опубликована;
- `failed` — попытка сорвалась (текст ошибки рядом); бот повторяет каждые 5 минут до полуночи.

### Работа с базой напрямую

Запросы удобно выполнять через контейнер — модуль `db` уже внутри:

```bash
docker compose exec -T tg_summary_bot python -c "
import db
c = db.connect('data/bot.db')
for r in c.execute('SELECT chat_id, day_state, day, last_message_id FROM summary_state'):
    print(dict(r))
"
```

Отметка места — поле `summary_state.last_message_id`; сводка берёт сообщения строго после
неё. Сдвинуть отметку (чтобы следующая сводка охватила больше или меньше):

```bash
docker compose exec -T tg_summary_bot python -c "
import db
c = db.connect('data/bot.db')
c.execute('UPDATE summary_state SET last_message_id = ? WHERE chat_id = ?', (6000, -1001234567890))
c.commit(); print('ok')
"
```

Чтобы бот повторил попытку сегодня, верните состояние дня в `waiting`:

```bash
docker compose exec -T tg_summary_bot python -c "
import db
c = db.connect('data/bot.db')
c.execute(\"UPDATE summary_state SET day_state='waiting' WHERE chat_id=?\", (-1001234567890,))
c.commit(); print('ok')
"
```

Схема базы и назначение таблиц — в [`docs/спецификация.md`](docs/спецификация.md), раздел
«База данных».

## Разбор неполадок

**Сводки нет, а должна быть.** Смотрите `data/bot.log`. Обычные причины: сообщений меньше
порога (состояние `skipped`), сбой модели или сети (`failed` и текст ошибки), назначенное
время ещё не наступило.

**`Conflict: terminated by other getUpdates`.** Запущены два экземпляра бота на одном токене.

**Бот не видит сообщений группы.** Не отключён режим приватности — `/setprivacy` у @BotFather.
Проверить, доходят ли обновления вообще, помогает `python listen_raw.py 60` (запускать
локально, при остановленном контейнере): скрипт слушает `getUpdates` напрямую и печатает
всё, что приходит от Telegram.

**Реакции не отмечают сообщения.** Бот должен быть администратором чата, и учитываются только
реакции, поставленные после того, как он им стал.

**Время публикации не совпадает.** Планировщик считает время по Москве независимо от пояса
сервера (сервер в UTC — это нормально). См. константу `MSK` в `scheduler.py`.

**OpenRouter или Telegram недоступны.** Если они не открываются с вашего сервера напрямую,
заполните `PROXY` в `.env` и выполните `docker compose up -d`.

**Импорт файла не проходит.** Файл больше 20 МБ облачный Bot API не отдаёт — режьте выгрузку
по периодам.

## Локальный запуск без Docker

Нужны заполненные `.env` и `config/chats.yaml` — те же, что и для контейнера.

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python bot.py
```

В Windows пути к окружению другие: `.venv\Scripts\pip` и `.venv\Scripts\python`.

Помните про один экземпляр на токен: серверный контейнер на это время нужно остановить.
Для отладки удобно завести у @BotFather второго бота со своим токеном и отдельный чат под него.

## Ограничения Telegram, которые не обойти

- Бот не видит историю чата до своего добавления — только выгрузкой.
- Бот **никогда** не видит сообщения других ботов.
- Реакции — только при правах администратора и только за период после подключения.
- Скачивание присланных файлов — до 20 МБ.
- Сообщение длиннее 4096 знаков Telegram не примет. Поэтому бот обрезает ответ модели до 4000
  знаков ещё до наложения разметки и пишет об этом в лог. На части не разбивает: обрезка —
  сигнал доработать промпт или сменить модель.
